# CPU reference limits

`knolo.micro.v1` is a checked-in f32 transformer: 2 layers, hidden size 8, vocabulary 16, and one KV block of 16 tokens. The plain f32 oracle in `infer-engine` is the numerical authority. Candle 0.8.4 on CPU must match its prefill logits and KV values within absolute tolerance `1e-4`, and it must emit the same greedy token ids. The formulas and tensor names are in `spec/KIP-INFER-0003-cpu-micro-transformer.md`.

Failure behavior:

- An adapter other than `knolo.micro.v1` is `UNSUPPORTED_ARCHITECTURE` and does not open weights.
- A weight file is hashed before its safetensors header or body is read. A mismatch is `MODEL_DIGEST_MISMATCH`.
- A non-f32 tensor is `UNSUPPORTED_QUANTIZATION`.
- A placement that is not a single CPU f32 block of 16 is `PLACEMENT_UNSATISFIABLE`.
- A prompt that does not fit, including one of 17 tokens, is `CONTEXT_LIMIT_EXCEEDED`. Tokens are not truncated.
- An empty prompt or a token id outside the vocabulary is `PROMPT_COMPILATION_FAILED`.
- A backend other than `reference-f32` or, in `infer-native`, `candle-cpu` is `UNSUPPORTED_KERNEL`.

The fixed-count oracle helper is lowest-index argmax and does not stop on the end-of-sequence id. `knolo-infer run` uses the sampler: temperature 0 is that same argmax, and a non-zero temperature draws from Philox-4x32-10. Generation stops on the end-of-sequence id or the token budget.

Oracle tests keep one block per sequence and refuse a ninth sequence with `INSUFFICIENT_MEMORY`. The run command uses a pool of eight pages of 16 tokens, specified in `spec/KIP-INFER-0005-paged-kv.md`. The micro context fits in one page. A new page is `INSUFFICIENT_MEMORY` while eight active sequences hold the pool. Released pages are zeroed and the lowest free id is reused. An inactive sequence can be evicted. An active sequence cannot. Prefix cache is not allocated.

The default run command records a CPU engine build and, when `nvidia-smi` answers, the visible GPU. Placement stays on `cpu`. When `nvcc` is on `PATH`, that probe records the toolkit release. `infer-native` can run the same micro-model on GPU `slot-0` with `--features cuda`, as specified in `spec/KIP-INFER-0021-candle-cuda.md`. `knolo-infer run --features cuda` selects that device and names it on the receipt, as specified in `spec/KIP-INFER-0022-cuda-run.md`. `knolo-infer serve --features cuda` selects it for the worker, as specified in `spec/KIP-INFER-0023-cuda-serve.md`. `knolo-infer run` does not serve HTTP.

`CpuScheduler` is the continuous path on that same pool. It is specified in `spec/KIP-INFER-0006-cpu-scheduler.md`. A request whose prompt plus token budget exceeds 16 tokens is `CONTEXT_LIMIT_EXCEEDED`. A request that needs a page the active sequences already hold is `INSUFFICIENT_MEMORY`. The scheduler does not shorten the prompt or the budget, and it does not evict an active sequence. Finish reasons on this path are `stop`, `length`, `cancelled`, and `error`. `knolo-infer run` still uses one isolated sequence.

`knolo-infer serve` is the supervisor in `spec/KIP-INFER-0007-cpu-supervisor.md`. It listens on `127.0.0.1` only. The worker process is `knolo-infer-worker`. It loads the pinned weights, runs that same scheduler with a prefill chunk of 4, and does not bind a TCP port. A finished HTTP completion carries output text, token ids, the runtime root, and a receipt id. A cancellation does not store a receipt. A worker crash fails the in-flight request with `WORKER_LOST` and leaves the listener up. The next request starts a new worker. `GET /metrics` publishes the Prometheus series in `spec/KIP-INFER-0010-metrics.md`. The worker answers that scrape with counters; the scrape does not sample a token. `POST /knolo/infer/v1/drain` stops new completions and lets an admitted request finish. The worker stays loaded. That call is specified in `spec/KIP-INFER-0012-drain.md`. `POST /knolo/infer/v1/models/unload` lets admitted work finish, then the worker zeros its KV pages and exits. A later completion does not start a worker. That call is specified in `spec/KIP-INFER-0013-unload.md`. `POST /knolo/infer/v1/models/load` starts that pin again after the worker has exited. Admitted work still finishes first. Drain stays in force. That call is specified in `spec/KIP-INFER-0014-restart.md`. A finished request is dropped after its result is written, so a later completion does not keep the earlier prompt in the scheduler. The page pool stays at the size allocated when the worker started. That bound is specified in `spec/KIP-INFER-0015-bounded-memory-soak.md`. One serve process owns `{home}/daemon.lock`. A second process leaves that owner in place. A dead owner's lock is taken, and a journal that stopped after `accepted` is sealed `failed` before the listener binds. That recovery is specified in `spec/KIP-INFER-0016-crash-recovery.md`.

GGUF `F16`, `Q8_0`, `Q4_K`, `Q5_K`, and `Q6_K` dequant to finite `f32` in this crate. The payload is not rewritten and no converted weight file is produced. The byte layout and the 32 MiB output cap are specified in `spec/KIP-INFER-0017-gguf-dequant.md`, `spec/KIP-INFER-0018-q6k-dequant.md`, `spec/KIP-INFER-0019-q5k-dequant.md`, and `spec/KIP-INFER-0020-q4k-dequant.md`. `quant_gemm` multiplies an allowlisted payload by `f32` activations, one decoded block at a time, as specified in `spec/KIP-INFER-0024-quant-gemm.md`. The product is a new buffer. An explicit conversion, specified in `spec/KIP-INFER-0025-conversion-receipt.md`, writes a new little-endian `f32` artifact and a conversion receipt.
